TASK QUEUE: M4 Workout Tracking. Same rules as M3: all database code in src/main/db/, snake_case names, ISO text timestamps, dates as YYYY-MM-DD text, no new dependencies. Weights are always stored in kilograms; the UI converts using user_profile.units.

Data model decision: a "workout" row is one performed training session (name, date, duration, notes). The roadmap's "WorkoutSession" table (M4-002) is implemented as workout_exercise: one exercise slot inside a workout, in order. Sets belong to a workout_exercise. Chain: workout -> workout_exercise -> set_log, deletes cascade down; deleting an exercise that has been logged is rejected.
